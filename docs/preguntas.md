# Evaluación: Prototipos y Wireframes

Banco de 10 preguntas de opción múltiple para cargar o recrear en **Wayground**. Cada pregunta tiene una respuesta correcta. Se recomienda ocultar las respuestas al presentar el cuestionario a la clase.

## 1. ¿Qué es un wireframe?

- A. El código final de una aplicación.
- B. Un esquema que comunica estructura, jerarquía y controles de una interfaz.
- C. Un informe de errores de programación.
- D. Una base de datos con el contenido del sistema.

**Respuesta correcta: B.** Un wireframe representa la organización de una o varias pantallas antes de definir todos los detalles visuales.

## 2. ¿Cuál describe mejor un wireframe de baja fidelidad?

- A. Tiene todos los colores, imágenes y animaciones finales.
- B. Es una versión publicada y completamente funcional del producto.
- C. Muestra principalmente la estructura y puede usar formas y etiquetas sencillas.
- D. Solo puede realizarse después de programar la interfaz.

**Respuesta correcta: C.** La baja fidelidad prioriza estructura e interacción principal sobre el acabado visual.

## 3. ¿Para qué sirve principalmente un sitemap?

- A. Para representar la jerarquía de secciones o pantallas de un sistema.
- B. Para mostrar el código fuente de cada pantalla.
- C. Para medir la velocidad de internet.
- D. Para registrar las respuestas de una evaluación.

**Respuesta correcta: A.** El sitemap muestra cómo se organiza el contenido y qué secciones forman parte de la solución.

## 4. ¿Qué representa un user flow?

- A. Los colores permitidos para los botones.
- B. La lista de integrantes de un equipo.
- C. El presupuesto completo del proyecto.
- D. Los pasos y decisiones que sigue una persona para completar una tarea.

**Respuesta correcta: D.** El user flow muestra el recorrido, las acciones y, cuando corresponde, las decisiones o resultados.

## 5. ¿Por qué un wireframe de baja fidelidad suele evitar colores y fotografías finales?

- A. Porque los colores nunca se deben usar en interfaces.
- B. Para enfocar la revisión en estructura, jerarquía y tarea antes de los detalles estéticos.
- C. Porque un wireframe no puede contener texto.
- D. Para impedir que el equipo haga cambios.

**Respuesta correcta: B.** Al reducir detalles visuales, se puede discutir con más claridad la estructura y la navegación.

## 6. ¿Cuál de estos es un componente de interfaz?

- A. Un requisito de la asignatura.
- B. Una reunión del equipo.
- C. Un botón para agregar un producto al pedido.
- D. Una carpeta del repositorio.

**Respuesta correcta: C.** Un botón es un control de interfaz que permite realizar una acción.

## 7. ¿Qué beneficio puede aportar revisar wireframes antes de programar?

- A. Garantiza que nunca habrá errores ni cambios.
- B. Evita tener que comprender los requisitos.
- C. Hace innecesario evaluar la solución con usuarios.
- D. Puede revelar problemas temprano y reducir retrabajo por cambios tardíos.

**Respuesta correcta: D.** Detectar problemas de estructura pronto puede evitar correcciones más costosas durante la implementación.

## 8. ¿Qué busca la arquitectura de información?

- A. Organizar el contenido y las funciones para que sean comprensibles y fáciles de encontrar.
- B. Elegir el lenguaje de programación más rápido.
- C. Crear las ilustraciones decorativas de una interfaz.
- D. Asignar calificaciones a los integrantes.

**Respuesta correcta: A.** La arquitectura de información organiza el contenido y ayuda a orientar la navegación.

## 9. ¿Cuál debería ser el primer paso al pasar de un requisito a una interfaz?

- A. Elegir las animaciones.
- B. Analizar la necesidad, el usuario y la tarea que se quiere resolver.
- C. Programar todas las pantallas.
- D. Seleccionar los colores definitivos.

**Respuesta correcta: B.** Primero hay que entender qué necesita hacer la persona y en qué contexto.

## 10. ¿Cuál es una herramienta que puede utilizarse para elaborar wireframes?

- A. Un reproductor de música.
- B. Una calculadora solamente.
- C. Figma.
- D. Un compilador de bases de datos únicamente.

**Respuesta correcta: C.** Figma permite crear wireframes y prototipos; también se puede empezar con papel y lápiz u otras herramientas.
